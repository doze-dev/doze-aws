What happens when you use them
Tried here under --iam-mode enforce, with harbour-states-exec, which has no policies at all:
sqs list-queuesanswered
sts get-caller-identityuser/test
The role's lack of policies did not matter, because the key id is not one a user owns, so the call is the account root. The same call signed with a user's key is judged by that user's policies.
1Nothing is looked up. The role need not exist: AssumeRole mints for any well-formed role ARN. The role's trust policy is not read.
2The expiry is a field, not a deadline. Every service accepts any signature, or none, so an expired set still works.
3To test a role, simulate it against the actions you care about, or sign calls with a user's access key and read the access log.
