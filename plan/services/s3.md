# S3

Stage 6. Size L. Follows [../01-protocol.md](../01-protocol.md); the common
acceptance criteria there apply in full, and this page adds S3's own.

## 1. Summary

Buckets and objects over one bbolt store plus a blob tree on disk
(`internal/s3store`), speaking restXml in both addressing styles. It carries the
functional bucket features: versioning, object lock, CORS preflight, lifecycle
(a janitor that ticks once a minute), website documents, the public access
block, the bucket policy, and event notifications. Peers: it delivers
notifications into SQS, SNS and Lambda; Lambda stages code from it; Step
Functions reads and writes it; CloudFormation and `provision` create it.

It is L for three reasons. The contract is the largest in the stack (112
operations). The object-lock and lifecycle paths have behaviour bugs that change
what an app sees (S3-2, S3-3, S3-4, S3-22). And the console has more surfaces
than any other service's: an object browser, an object panel and seven
configuration editors, two of which lose data on a round trip (S3-6, S3-8).

**Estimate:** L, five or more focused days. My own breakdown is closer to
seven: two for the findings and the section 5 sweep, one for conformance and
recordings, three for the console, one for ledger and gates.
**Actual:** _fill in when done._

## 5. What to check

Beyond the common criteria. Each line on path-style **and** virtual-hosted
addressing where the request shape differs.

**Buckets**
- [ ] Every documented naming rule, one case each: length, charset, ends,
      adjacent periods, IP shape, reserved prefixes and suffixes.
- [ ] Create twice in us-east-1 and in another region (S3-15).
- [ ] Delete: empty, with objects, with only delete markers, with an unfinished
      upload; the code and message for each.
- [ ] `HeadBucket` on a missing bucket; `GetBucketLocation` in us-east-1 (empty)
      and elsewhere.
- [ ] `ListBuckets` paging members: establish and set the note.

**Objects**
- [ ] Key: 1,024 bytes accepted, 1,025 refused; keys with `+`, space, `%`,
      unicode and a trailing `/` round-trip through put, list, get and copy.
- [ ] Conditional reads and writes: each of If-Match, If-None-Match,
      If-Modified-Since, If-Unmodified-Since, and `If-None-Match: *` on put.
- [ ] Ranges: first, last, suffix, open-ended, unsatisfiable (416), multi-range.
- [ ] Every checksum algorithm, header- and trailer-declared, with a wrong value refused.
- [ ] Content-MD5 wrong value refused.
- [ ] Copy: onto itself with and without REPLACE, from a version, with a range
      (UploadPartCopy), each copy-source conditional, from a missing source.
- [ ] User metadata and the standard headers survive put, head, copy and restart.

**Listing**
- [ ] V1 and V2: prefix, delimiter, `max-keys` 0 and 1000 and above, every
      marker and token, `start-after`, `fetch-owner`, `encoding-type=url`.
- [ ] `ListObjectVersions`: order within a key, `IsLatest`, markers, both markers for paging.

**Versioning**
- [ ] Unversioned, Enabled, Suspended: put, overwrite, delete, delete by id,
      get by id, `null` ids, a marker as latest (404 with the marker header),
      get of a marker by id (405).
- [ ] Suspended on a lock bucket refused (`InvalidBucketState`, run).
- [ ] `MFADelete`: establish and set the tier.

**Multipart**
- [ ] Part numbers 1 and 10,000 accepted, 0 and 10,001 refused; parts out of
      order or with a wrong ETag at completion; a part under 5 MB that is not last.
- [ ] Complete twice; abort then complete; abort twice (`NoSuchUpload`, run).
- [ ] `ListParts` and `ListMultipartUploads` paging.
- [ ] The composite ETag and both checksum types.

**Tagging**
- [ ] Bucket and object: key 128 and 129, value 256 and 257, the character set,
      `aws:` prefix, duplicates, 10 and 11 object tags, 50 and 51 bucket tags.
- [ ] The `x-amz-tagging` header on put and the tagging directive on copy.

**Object lock**
- [ ] Default retention applied to a new version, in days and in years, and not
      to a put that carries its own (S3-3).
- [ ] Mode and date transitions: every pair of (none, GOVERNANCE, COMPLIANCE)
      by (shorter, longer), with and without the bypass header (S3-22).
- [ ] Past date (S3-23). Legal hold on and off; delete of a held version.
- [ ] `x-amz-object-lock-*` headers on PutObject and CreateMultipartUpload.
- [ ] Enabling lock on an existing bucket, versioned and not (S3-21).
- [ ] The janitor and a locked noncurrent version: what the sweep does, and
      that it does not log a deletion that did not happen.

**Lifecycle**
- [ ] Each member in the section 2 table has a test that shows its tier.
- [ ] No action, duplicate ids, id over 255, more than 1,000 rules.
- [ ] Noncurrent age from the moment of supersession (S3-24).
- [ ] Expiry on a versioned bucket adds a marker; on a suspended one, a null marker.
- [ ] Whether expiry sends a notification: establish (section 2).

**CORS**
- [ ] Methods and wildcard count at save (S3-16); more than 100 rules.
- [ ] Preflight: match, no match (403), header matching without case,
      `Vary`, `MaxAgeSeconds` 0 and unset, and decoration of a simple request.

**Website**
- [ ] Suffix rules (S3-18); index at a sub-directory, at the root (S3-11),
      error document present and missing; `RedirectAllRequestsTo` and
      `RoutingRules` tier.

**Notifications**
- [ ] Destination validation (S3-5); overlap; each event type in the section 2
      row either sent or documented as not sent.
- [ ] Filter: prefix only, suffix only, both, neither; key encoding in the record.
- [ ] The record's shape against AWS's (version 2.1 fields, `sequencer`, `versionId`).
- [ ] Batch delete (S3-4) and versioned delete (S3-38).

**Policy and public access**
- [ ] Each malformed-policy shape, its code and message (S3-25, S3-26).
- [ ] Root can always read, replace and delete the bucket policy (S3-27).
- [ ] Each context key AWS documents as always present reaches the evaluator (S3-28).
- [ ] `BlockPublicPolicy` on a public policy; a policy stored before the block
      is turned on stays and reports public; `RestrictPublicBuckets` tier.
