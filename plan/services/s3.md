### Classes of mistake this service is most at risk of

1. **A valid member accepted and ignored.** S3 has 736 header bindings and the
   code reads a few dozen. Every row of L2 above is this. The test to write for
   the whole class is mechanical: for each input member in the model that the
   service does not read, either read it or refuse it with the model's code;
   `s3/declared_headers_test.go` is the place and currently covers only the
   headers it lists.
2. **A rule that deletes data on a wrong reading.** The lifecycle engine reads
   one filter shape and treats every other as "the whole bucket" (S3-39). The
   same engine counts time from the wrong moment (S3-24, S3-40). Both are P0 or
   P1 and neither needs AWS to be consulted.
3. **Pagination written once for the common case.** Each of the six list
   operations has a paging or shape defect: three ignore the model's markers
   and maxima outright (S3-51 to S3-53), the object listings have no cap and
   an echoing token (S3-49, S3-50).
4. **Configuration documents stored raw.** Nine documents are kept as the XML
   that arrived and validated by "parses as XML". Every refusal AWS makes on
   their contents (S3-16, S3-17, S3-18, S3-59, S3-74, S3-79) is missing, and
   the console editors then lose what they cannot model (S3-2, S3-6, S3-8).
5. **The console built from the boards' sentences and not their shape.** The
   same defect as SQS: 22 of 26 boards differ in shape.

### Decisions this review needs from a person

1. **A website host** (S3-11, S3-74): serve website behaviour only on
   `<bucket>.s3-website.<region>.<suffix>` as AWS does, leaving the REST path
   plain. Recommended. The alternative is to keep the REST-path behaviour and
   say so; it is what the Serverless and CDK static-site tests hit today.
2. **`GetObject` of a GLACIER or DEEP_ARCHIVE object** (S3-57): refuse with
   `InvalidObjectState` as AWS does (and let `RestoreObject` stay a stub), or
   serve it and list the difference. Recommended: refuse; a test of an app's
   restore path cannot work either way, and a silent success hides the bug.
3. **`MFADelete`** (S3-85): store and echo it (tier C, said so) and do not
   require `x-amz-mfa`. Recommended.
4. **EventBridge notifications** (S3-72): deliver `Object Created` /
   `Object Deleted` to the default bus through the existing peers directory,
   or refuse `EventBridgeConfiguration` with `NotImplemented`. Recommended:
   deliver; the EventBridge service exists and a stored-and-silent setting is
   the worst of the three.
5. **`RestrictPublicBuckets`** and **event holds** (S3-61): tier C and said so,
   or build. Recommended: C now.
6. **Account-regional namespace** (`x-amz-bucket-namespace`, the `-an`
   suffix): accept and name-check, or S. Recommended: name-check only.

## 1. Summary

Buckets and objects over one bbolt store plus a blob tree on disk
(`internal/s3store`), speaking restXml in both addressing styles. It carries the
functional bucket features: versioning, object lock, CORS preflight, lifecycle
(a janitor that ticks once a minute), website documents, the public access
block, the bucket policy, and event notifications. Peers: it delivers
notifications into SQS, SNS and Lambda; Lambda stages code from it; Step
Functions reads and writes it; CloudFormation and `provision` create it.

It is **XL**, for four reasons. The contract is the largest in the stack (112
operations, 74 routed). The behaviour bugs are not three or four: the review
found **47 more findings on top of the 37 the page listed**, among them a P0 in
the lifecycle engine that expires objects the rule never named (S3-39). Every
one of the six list operations has a paging or shape defect. And the
console has more surfaces than any other service's (an object browser, an object
panel and seven configuration editors) and **22 of its 26 boards differ in
shape** from the dream design.

**Estimate (re-done 2026-10-11, honest):** XL, **about twenty focused days**
(range 15 to 28), in three sub-stages that can each be signed off:
- **6a, the API** (8 to 10 days): the 84 findings, the section 5 sweep, the
  store changes they need (part sizes kept after completion; opaque tokens;
  per-version lock fields; lifecycle filters, rounding and noncurrent counting;
  the website host; destination validation and the test event; default
  ownership and bucket region), parity cases with codes, restart tests.
- **6b, conformance and recordings** (2 days): 22 new scenarios on top of the
  10, and the claims table.
- **6c, the console** (6 to 8 days): the 22 boards that differ, the seven
  sub-pages of Properties with their teaching lines and the S3 settings table,
  the inline object inspector, eight confirms with bodies, and 27 browser
  tests brought up to refusal text.
- **Gates and ledger** (2 days).

SQS was sized S at two days, closed 29 findings where 8 were listed, and rebuilt
six boards; its sizing was several times low. This page was 37 findings and
"five or more days, my own breakdown closer to seven"; with 84 findings, a
store change behind a third of them and 22 boards, the number above is the
honest one. If it must be one stage, size it XL and do not call it done at 6a.

## 5. What to check

Beyond the common criteria. Each line on path-style **and** virtual-hosted
addressing where the request shape differs. S3 declares one protocol (restXml),
so there is no second wire to check; the matrix is addressing style by SDK
generation, and every line below is one `sdk_coverage_test.go`-style case.

**Buckets**
- [ ] Every documented naming rule, one case each: length 3 to 63, charset,
      begin and end, adjacent periods, IP shape, the three prefixes and five
      suffixes (S3-14), `-an` only with `x-amz-bucket-namespace`.
- [ ] Create twice in us-east-1 and in another region (S3-15); create with
      `LocationConstraint`, `Tags`, `x-amz-object-ownership`, `x-amz-acl`
      (S3-68); a new bucket's ownership controls (S3-69); `GetBucketLocation`
      in us-east-1 (empty) and elsewhere (S3-70).
- [ ] Delete: empty, with objects, with only delete markers, with an unfinished
      upload (S3-76: record first); the code and message for each.
- [ ] `HeadBucket` on a missing bucket (404, no body); `ExpectedBucketOwner` on
      every operation that has it (S3-43).
- [ ] `ListBuckets` `max-buckets`, `continuation-token`, `prefix`,
      `bucket-region` (S3-51).

**Objects**
- [ ] Key: 1,024 bytes accepted, 1,025 refused (S3-20); keys with `+`, space,
      `%`, unicode and a trailing `/` round-trip through put, list, get and copy.
- [ ] User metadata at 2,048 and 2,049 bytes (S3-56).
- [ ] Conditional reads and writes: each of If-Match, If-None-Match,
      If-Modified-Since, If-Unmodified-Since, the documented pairs (S3-47), and
      `If-None-Match: *` and `If-Match` on put, copy (S3-45) and complete.
- [ ] Ranges: first, last, suffix, open-ended, unsatisfiable (416); multi-range
      ("Amazon S3 doesn't support retrieving multiple ranges", `model`; what it
      answers is memory); `partNumber` (S3-54); the `response-*` overrides
      (S3-55).
- [ ] Every checksum algorithm in the model's enum (ten, S3-65), header- and
      trailer-declared, with a wrong value refused; the default CRC64NVME.
- [ ] Content-MD5 wrong value refused (`BadDigest`), malformed (`InvalidDigest`).
- [ ] Copy: onto itself with and without REPLACE, from a version, from a
      multipart object (S3-46), with `x-amz-storage-class` (S3-44), with a
      range (UploadPartCopy, S3-48), each copy-source conditional, from a
      missing source, from a delete marker (404; a versioned id: 400).
- [ ] User metadata and the standard headers survive put, head, copy and restart.
- [ ] GLACIER and DEEP_ARCHIVE (S3-57, decision 2).

**Listing**
- [ ] V1 and V2: prefix, delimiter, `max-keys` 0, 1, 1000, 1001 and 2000 (S3-49),
      every marker and token, a garbage token (S3-50), `start-after`,
      `fetch-owner`, `encoding-type=url`.
- [ ] `ListObjectVersions`: order within a key, `IsLatest`, markers, both markers
      for paging, `max-keys`.
- [ ] `ListParts` and `ListMultipartUploads` paging (S3-52, S3-53).

**Versioning**
- [ ] Unversioned, Enabled, Suspended: put, overwrite, delete, delete by id,
      get by id, `null` ids, a marker as latest (404 with the marker header),
      get of a marker by id (405 with `Last-Modified`, `doc`).
- [ ] Suspended on a lock bucket refused (`InvalidBucketState`, run).
- [ ] `MFADelete` (S3-85, decision 3); a malformed version id (S3-77).

**Multipart**
- [ ] Part numbers 1 and 10,000 accepted, 0 and 10,001 refused (`model`);
      parts out of order or with a wrong ETag at completion; a part under 5 MB
      that is not last; `x-amz-mp-object-size` (S3-62).
- [ ] Complete twice; abort then complete; abort twice (`NoSuchUpload`, run);
      abort with `x-amz-if-match-initiated-time` (S3-63).

      `partNumber` and `ObjectParts` (S3-54).
- [ ] `CreateMultipartUpload` with lock, storage class, tagging (S3-60).

**Tagging**
- [ ] Bucket and object: key 128 and 129, value 256 and 257, the character set,

- [ ] The `x-amz-tagging` header on put and the tagging directive on copy.

**Object lock**
- [ ] Default retention applied to a new version, in days and in years, and not
      to a put that carries its own (S3-3).
- [ ] Mode and date transitions: every pair of (none, GOVERNANCE, COMPLIANCE)

- [ ] Batch delete (S3-4), versioned delete (S3-38), lifecycle (S3-42),

**Policy and public access**
- [ ] Each malformed-policy shape, its code and message (S3-25, S3-26).
- [ ] Root can always read, replace and delete the bucket policy (S3-27).
- [ ] Each context key AWS documents as always present reaches the evaluator

**Presigned URLs**
- [ ] SigV4 and SigV2 GET and PUT; expired; `X-Amz-Expires` over seven days.

**Stubs and cosmetics**

- [ ] Every C document round-trips and its delete works; the validation AWS

**Lifecycle of state**
