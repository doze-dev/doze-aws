Point your tooling at this endpoint. Every block below is the same fact in a different dialect, built from the address you actually reached the console on.
AWS CLI profile

A named profile keeps every later command short, and leaves your real AWS credentials untouched.

~/.aws/config
[profile doze]
region = {{.Region}}
output = json
endpoint_url = {{.URL}}
~/.aws/credentials
[doze]
aws_access_key_id = {{.Key}}
aws_secret_access_key = {{.Secret}}
then
aws --profile doze s3 ls
aws --profile doze sqs list-queues

endpoint_url in a profile needs AWS CLI v2.13 or newer. On anything older, use the environment block instead.

Environment

No files touched. Every AWS SDK reads these, so it works for one-off shells and CI alike.

shell
export AWS_ENDPOINT_URL={{.URL}}
export AWS_ACCESS_KEY_ID={{.Key}}
export AWS_SECRET_ACCESS_KEY={{.Secret}}
export AWS_REGION={{.Region}}
Terraform
provider.tf
provider "aws" {
  region                      = "{{.Region}}"
  access_key                  = "{{.Key}}"
  secret_key                  = "{{.Secret}}"
  skip_credentials_validation = true
  skip_requesting_account_id  = true
  s3_use_path_style           = true

  endpoints {
    s3       = "{{.URL}}"
    sqs      = "{{.URL}}"
    sns      = "{{.URL}}"
    dynamodb = "{{.URL}}"
    lambda   = "{{.URL}}"
  }
}
Deploy with what you already have

There is no doze-specific file format. These read the environment above and need no further setup.

deploy
aws cloudformation deploy --template-file template.yaml --stack-name shop
sam deploy --stack-name shop --s3-bucket artifacts
cdk bootstrap && cdk deploy
